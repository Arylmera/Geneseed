Accessibility for React components: what to write, and what the reviewer will refuse.

## Semantic HTML first
- A clickable thing is a `<button>` (an action) or an `<a href>` (navigation). `<div onClick>` is not keyboard-reachable and has no role; do not add `role` and `tabIndex` to make it one.
- One `<main>`, landmarks (`<nav>`, `<header>`, `<footer>`), headings in order without skipped levels.
- `<img>` always has `alt`: a description for content, `alt=""` for decoration. An icon-only button has `aria-label`.

## Forms
- Every input has a label: `<label htmlFor={id}>` with `useId()` for the id, or `aria-label` when the label is visual only.
- Required fields carry `required` (or `aria-required`), not only a red asterisk.
- An error is linked with `aria-describedby`, flags the field `aria-invalid="true"`, and is announced (`role="alert"` on the message). Never signal an error by colour alone.
- Use a real `<form>` with `onSubmit` so Enter submits; inputs have a `name`.

## Dynamic content
- A status that changes without focus moving (saved, loading, results count) sits in an `aria-live="polite"` region that is present before its text changes.
- A disclosure (accordion, dropdown) toggles `aria-expanded` on its trigger and points `aria-controls` at the panel.

## Keyboard and focus
- Every interaction works with Tab, Shift+Tab, Enter, Space and Escape. A custom widget (menu, listbox, tabs) follows the WAI-ARIA Authoring Practices pattern for it, arrow keys included; prefer the project's component library over hand-rolling one.
- A modal moves focus into itself on open, traps it, closes on Escape and returns focus to the trigger on close. The native `<dialog>` with `showModal()` does most of this.
- On a client-side route change, move focus to the new page's heading or main region.
- Never remove the focus outline without a visible replacement (`:focus-visible`).

## Motion
Respect `prefers-reduced-motion`: disable or shorten non-essential animation under it.

## Checking
- `eslint-plugin-jsx-a11y` in the lint config.
- `jest-axe` in component tests for interactive components (react-testing skill). jsdom has no layout, so contrast and focus-visible need a real browser check.
