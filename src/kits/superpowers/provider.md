### Workflow provider

The `superpowers` kit is off, so the official superpowers plugin is this install's provider of the brainstorm, debug, plan, code-review and review-response {{SKILLS}}.

1. **Rank.** The plugin's {{SKILLS}} are procedure, never rank. "Invoke it at a 1% chance" never outranks a {{LAW}}, a user rule or a {{DOCTRINE}}.
2. **Routing.** `{{PLUGIN_PREFIX}}dispatching-parallel-agents`, `{{PLUGIN_PREFIX}}subagent-driven-development` and `{{PLUGIN_PREFIX}}executing-plans` are allowed, but the parent writes every worker's brief by the parallel-agents {{SKILL}}'s Brief checklist (BASE, write set, proof commands, commit only in its own worktree). `{{PLUGIN_PREFIX}}finishing-a-development-branch` yields to the ship {{SKILL}}: main changes only through a pull request with green checks. `{{PLUGIN_PREFIX}}test-driven-development` yields to the develop {{SKILL}}, `{{PLUGIN_PREFIX}}using-git-worktrees` to worktree, and `{{PLUGIN_PREFIX}}writing-skills` to skill-forge.
3. **Missing provider.** If no superpowers skill is in your inventory, tell the user once: turn on the `superpowers` kit or install the superpowers plugin.
